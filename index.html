📬 Seção 1

O que é MX e Whois

Registro MX (Mail Exchanger)

O registro MX indica qual servidor de e-mail deve receber mensagens para aquele domínio. Sem MX configurado, e-mails enviados para @devfelipelima.com.br não chegam a lugar nenhum.

Remetente

Envia e-mail para devfelipelima.com.br

→
Consulta MX

DNS resolve qual servidor recebe

→
Servidor MX

mail.devfelipelima.com.br

→
Entrega

Mensagem chega na caixa de entrada

📄 Exemplo de registro MX — devfelipelima.com.br
Nome/HostTipoTTLPrioridadeValor/Destino
devfelipelima.com.br MX 3600 10 mail.devfelipelima.com.br
💡
Prioridade MX

Números menores = maior prioridade. Se houver dois registros (prioridade 10 e 20), o servidor tenta o 10 primeiro. Se falhar, tenta o 20.

O que é Whois

Whois é uma consulta pública que revela quem é o dono de um domínio, quando foi registrado, quando expira, e principalmente: quais são os Nameservers (NS) — ou seja, onde o DNS está hospedado.

MXToolbox Whois
mxtoolbox.com → SuperTool → Whois

Digite o domínio e encontre os nameservers (nserver). Esses nservers mostram onde o DNS está configurado.

Whois Registro.br
registro.br/cgi-bin/whois

Para domínios .com.br, o Registro.br exibe todos os dados do titular e dos nameservers de forma detalhada.

3

No resultado você verá algo como:

⚙️ Seção 4

Campos do Painel DNS — o que é cada um

Em todos os painéis de DNS, você vai encontrar basicamente os mesmos campos. Entender cada um é essencial para não errar na hora de cadastrar.

📋 Referência de Campos DNS
CampoTambém chamado deO que colocar
Nome / Host / Subdomínio Name, Label, Subdomain A parte antes do domínio. Use @ para a raiz, ou seletor._domainkey para subdomínios. Em alguns painéis você digita só o prefixo (sem o domínio); em outros o FQDN completo.
Tipo Type, Record Type TXT, MX, CNAME, A, AAAA… Selecione exatamente o tipo informado.
TTL Time to Live Tempo em segundos que o cache dura. Use 3600 (1 hora) como padrão. Para mudanças urgentes, reduza para 300 antes.
Valor / Registro / Conteúdo Value, Data, Content, Target, Points to O conteúdo real do registro. Para TXT é a string entre aspas; para CNAME é o destino; para MX é o hostname do servidor.
Prioridade Priority, Preference Só aparece para MX. Número inteiro; menor = prioridade maior.
⚠️
Atenção: ponto final (FQDN)

Alguns painéis (ex: cPanel, BIND) exigem ponto final no valor: mail.devfelipelima.com.br. — sem o ponto, ele adiciona o domínio automaticamente e o registro fica errado. Painéis modernos (Route 53, Cloudflare, Azure) geralmente não precisam do ponto.

🛡️ SPF

O que é SPF

Sender Policy Framework — define quais servidores têm permissão para enviar e-mails em nome do seu domínio. Funciona como uma "lista de convidados": se o servidor não estiver na lista, o e-mail pode ser rejeitado ou marcado como spam.

Como funciona

E-mail enviado

pelo servidor m3.messagecenter

→
Servidor receptor

consulta SPF do domínio remetente

→
Verifica TXT

include:m3.messagecenter.com.br

→
✅ PASS

Entrega autorizada

Registro SPF que passamos ao cliente

Registro TXT — devfelipelima.com.br 
v=spf1 include:m3.messagecenter.com.br ~all

# Se o cliente já tiver um SPF existente, NÃO crie um segundo registro.
# Adicione o include dentro do registro já existente:
v=spf1 include:gmail.com include:m3.messagecenter.com.br ~all
🚫
Nunca crie dois registros SPF no mesmo domínio!

Um domínio deve ter somente um registro SPF (TXT começando com v=spf1). Dois registros causam falha de autenticação imediata (PermerError).

Cheatsheet SPF — Mecanismos e Qualificadores

🔧 Qualificadores (final do registro)
SímboloNomeEfeito quando não bateQuando usar
+all Pass all Aprova qualquer servidor INSEGURO Nunca — qualquer um pode enviar pelo seu domínio
~all SoftFail Aceita mas marca como suspeito MODERADO Fase de implementação / monitoramento
-all HardFail Rejeita servidores não autorizados RECOMENDADO Produção estável — quando todos os envios estão mapeados
?all Neutral Sem política definida INFORMATIVO Raríssimo — praticamente sem efeito
🔧 Mecanismos do SPF
MecanismoO que fazExemplo
include:Inclui a política SPF de outro domínio (adiciona os IPs dele)include:m3.messagecenter.com.br
ip4:Autoriza um IP ou bloco IPv4 específicoip4:200.10.20.30 ou ip4:200.10.0.0/24
ip6:Autoriza um endereço ou bloco IPv6ip6:2001:db8::1
aAutoriza o IP do registro A do domínioa:devfelipelima.com.br
mxAutoriza os IPs dos servidores MX do domíniomx
redirect=Usa a política SPF de outro domínio (substitui o atual)redirect=_spf.example.com

Limite de DNS Lookups — Regra dos 10

O SPF permite no máximo 10 consultas DNS (includes, mx, a, etc.). Se ultrapassar, o resultado é PermerError — falha permanente e autenticação quebrada.

Consultas utilizadas 3/10 — Válido ✅
Consultas utilizadas 11/10 — INVÁLIDO ❌
🛠️
Como verificar o SPF do cliente

Acesse easydmarc.com/tools/spf-lookup → digite o domínio → o resultado mostra o número de lookups. Se aparecer 3/10 = saudável. Se aparecer 11/10 ou mais = precisa otimizar (remover includes desnecessários ou usar "flattening").

Possíveis erros / invalidações do SPF

🚨 Problemas Comuns
ErroCausaSolução

TempErrorServidor DNS do domínio inacessível no momentoAguardar e verificar se o DNS está respondendo
HardFail (-all) + falta de includeServidor de envio não listado no SPFAdicionar o include correto antes do -all
Dois registros TXT v=spf1Cadastro duplicado por enganoMesclar em um único registro TXT
SPF em subdomínio erradoConfigurado em mail.dominio ao invés de dominioVerificar se o TXT está na raiz do domínio (@)

🔑 DKIM

O que é DKIM

DomainKeys Identified Mail — adiciona uma assinatura criptográfica em cada e-mail enviado. O servidor receptor consulta a chave pública no DNS e verifica se a mensagem não foi alterada em trânsito. É como um selo de autenticidade no envelope.

Cheatsheet: Seletor e Chave

🔑 Anatomia do DKIM
ConceitoO que éExemplo (devfelipelima)
Seletor Nome único que identifica o par de chaves. Permite ter múltiplos DKIMs no mesmo domínio. Geralmente começa com mc + parte do domínio. mcDevfelipelima
Chave Privada Fica no servidor de envio (mcenter). Assina cada e-mail. NUNCA é exposta. Gerenciada pelo app.mcenter.com.br
Chave Pública É o valor que o cliente cadastra no DNS como TXT. Qualquer servidor pode usar para verificar a assinatura. String p=MIGfMA0GCS...
Subdomínio DNS Sempre no formato: seletor._domainkey.dominio mcDevfelipelima._domainkey.devfelipelima.com.br

Como gerar o DKIM no mcenter

1
Acesse app.mcenter.com.br

Faça login e vá em Parâmetros → DKIM → Novo

2
Preencha o domínio e o seletor

Domínio: devfelipelima.com.br | Seletor: mcDevfelipelima (pode ser qualquer nome — use algo fácil de identificar)

3
Copie o registro TXT gerado

O sistema gera a chave pública que deve ser passada ao cliente para cadastrar no DNS.

Exemplo de registro gerado

Registro TXT DKIM gerado pelo mcenter 
# Nome/Host do registro:
mcDevfelipelima._domainkey.devfelipelima.com.br

# Valor do registro TXT:
v=DKIM1; k=rsa; p=MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQC5...
# (chave truncada — copie a chave completa gerada pelo mcenter)
📋 DKIM — devfelipelima.com.br
CampoValor a preencher
Nome / HostmcDevfelipelima._domainkey
TipoTXT
TTL3600
Valor / Conteúdov=DKIM1; k=rsa; p=MIGfMA0GCSqGSI...
⚠️
Atenção ao cadastrar o Host

Alguns painéis já adicionam o domínio automaticamente. Nesses casos, coloque apenas mcDevfelipelima._domainkey (sem o .devfelipelima.com.br). Se o painel exigir o FQDN completo, coloque mcDevfelipelima._domainkey.devfelipelima.com.br.

Como validar o DKIM

No MXToolbox: selecione DKIM Lookup → informe o domínio e o seletor (mcDevfelipelima) → resultado deve mostrar ✅ VALID.

📋 DMARC

O que é DMARC

Domain-based Message Authentication, Reporting and Conformance — é a política que diz ao servidor receptor o que fazer quando um e-mail falha no SPF e/ou DKIM. Além disso, gera relatórios de quem está enviando no nome do seu domínio.

📌
Pré-requisito

DMARC só funciona bem se SPF e DKIM já estiverem configurados. Sem eles, o DMARC não tem como verificar o alinhamento.

Cheatsheet DMARC — Tags e Valores

🔧 Tags do registro DMARC
TagO que fazValores possíveis
v=DMARC1 Versão — sempre presente e sempre DMARC1 DMARC1 (fixo)
p= Política principal — o que fazer com e-mails que falham none | quarantine | reject
sp= Política para subdomínios (se diferente da principal) none | quarantine | reject
rua= E-mail para receber relatórios agregados (diários) mailto:dmarc@devfelipelima.com.br
ruf= E-mail para relatórios forenses (por falha individual) mailto:dmarc@devfelipelima.com.br
pct= Porcentagem de e-mails afetados pela política 0-100 (padrão: 100)
adkim= Alinhamento DKIM r relaxed (padrão) | s strict
aspf= Alinhamento SPF r relaxed (padrão) | s strict
fo= Condições para envio de relatório forense 0 ambos falham | 1 qualquer um falha | d DKIM falha | s SPF falha
📊 Evolução recomendada da política DMARC
EtapaRegistroQuando usar
INÍCIO p=none v=DMARC1; p=none; rua=mailto:dmarc@devfelipelima.com.br Primeiros 2-4 semanas — monitoramento, sem bloqueio
MEIO p=quarantine v=DMARC1; p=quarantine; pct=50; rua=mailto:dmarc@devfelipelima.com.br Após análise dos relatórios, aplicar em 50% e aumentar gradualmente
FINAL p=reject v=DMARC1; p=reject; rua=mailto:dmarc@devfelipelima.com.br Produção estável — máxima proteção, rejeita 100% das falhas

Registro completo — devfelipelima.com.br

Registro TXT DMARC — fase inicial 
# Nome/Host:  _dmarc.devfelipelima.com.br
# Tipo:       TXT
# Valor:
v=DMARC1; p=none; rua=mailto:dmarc@devfelipelima.com.br; ruf=mailto:dmarc@devfelipelima.com.br; fo=1

Como validar o DMARC

No MXToolbox: selecione DMARC Lookup → informe devfelipelima.com.br. Resultado deve mostrar a política configurada. Se aparecer No DMARC Record Found, o registro ainda não propagou ou está com o host errado (lembre: deve ser _dmarc).

🔗 CNAME (Postmaster)

O que é CNAME — Google Postmaster Tools

O registro CNAME (Canonical Name) mapeia um nome para outro nome de domínio — é um apelido. No contexto do Google Postmaster Tools, utilizamos dois registros CNAME para verificar a propriedade do domínio e habilitar o monitoramento de reputação junto ao Gmail.

Por que o Google Postmaster é importante?

📊 Reputação do Domínio
postmaster.google.com

Monitora a reputação do domínio e do IP junto ao Gmail. Alto spam rate → e-mails na lixeira ou bloqueados.

📬 Taxa de Entrega
postmaster.google.com

Mostra o índice de spam, autenticação SPF/DKIM/DMARC e erros de entrega de forma visual.

Como gerar as chaves CNAME

1
Acesse postmaster.google.com

Login com a conta envio@enviodeboleto.com.br

2
Adicione o domínio do cliente

Clique em + Adicionar domínio → informe devfelipelima.com.br → o sistema gera automaticamente dois registros CNAME.

3
Copie as duas chaves geradas

Exemplo do que é gerado:

# CNAME 1:
Label/Host:  h312312j.devfelipelima.com.br
Destino:     141212315jdff.dv.googlehosted.com

# CNAME 2 (se solicitado):
Label/Host:  a9b8c7d6.devfelipelima.com.br
Destino:     987654321abcd.dv.googlehosted.com
4
Passe as chaves ao cliente para cadastrar no DNS

O cliente cadastra os dois registros CNAME no painel DNS dele.
